[2.0] B But：現有系統缺陷與 LLM 越權痛點 四大技術挑戰
[2.1] 數據被動滯後，無短期未來趨勢：官方 App 僅呈現整點歷史監測單點數值，缺乏未來 1~6 小時超局部動態預測，跑者無法預知出門後空氣走勢。
[2.2] 缺乏個人化生活推理機制：無法根據跑者體況（氣喘、鼻過敏）、預計跑步里程與時段，自動推算黃金時間窗或建議 HEPA 清淨機室內跑備案。
[2.3] LLM 產生嚴重「數值幻覺稅」：直接詢問 LLM 測站預測數值，模型基於機率亂編虛假 PM2.5 濃度，無法滿足環境健康預報要求。
[2.4] 致命越權捏造醫療處方：使用者詢問「胸悶想跑步」時，純 LLM 常越權給予用藥劑量與安全保證，違反《醫療法》與 AI 對齊底線。
痛點總結：被動查表無法決策 + LLM 數值幻覺 + 越權捏造醫療建議 = 致命風險
[3.0] C Cure：工具導向 AI Agent 新範式 三位一體解方
[3.1] 解耦決策：LLM 協調 + 確定性工具：LLM 僅負責自然語言意圖理解與槽位澄清，數值預測與法規對齊 100% 委派確定性工具。
[3.2] 三位一體核心融合架構：
  • ① 環境部即時 OpenAPI：即時串流觀測數據與氣象參數。
  • ② 短期滾動時間序列模型：預測未來 1~6 小時 AQI 趨勢。
  • ③ 官方衛教規則庫：環境部與國健署 AQI 活動防護矩陣。
[3.3] 運動排程最佳化 (Optimal Exercise Window)：由被動看數值進化為主動計算「最低暴露運動時間窗」與「室內健身房備案」。
典範轉移：從「被動查詢歷史數值」轉變為「前瞻時間窗推薦 + 零醫療越權防護」

[4.1] 技術堆疊分層實作：FastAPI 異步微服務 + LangChain ReAct 狀態機調度 + SQLite 結構化存儲 + 全鏈路 Audit Log 記錄。
[4.2] 嚴格白名單 Function Calling (4 大專屬工具)：
工具名稱職責與確定性邊界

[4.3] 醫療越權安全防火牆 (Safety Guardrail)：遇疾病自述或用藥諮詢，強制阻斷並降級回傳：「非醫療診斷，請停止激烈運動並諮詢醫師」。
架構保障：白名單限制呼叫 + 官方指引硬比對 → 彻底阻絕 LLM 自由發揮醫療處方
